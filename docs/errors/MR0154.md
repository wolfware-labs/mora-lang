# MR0154: `new` without a type, where no target type gives it a struct or a class to create

A `new` without a type, as in `new()` or `new { X = 1 }`, creates the type its place expects: the declared type of the local it initializes, the return type of the function it returns from, or the type of the parameter it is passed to. That type must be a struct or a class, since those are what `new` creates.

The error has two forms. Where the place expects no type, as for a `let` or `var` without a type or a `new()` written as a statement, there is nothing to create. An argument of a call with overloads expects the type that every overload able to take the arguments has at its position, and none when they differ. Where it expects a type of another kind, such as `int`, `string`, an option, an enum or an interface, `new` cannot create a value of it. In both cases only the author knows which type is meant, so there is no fix: write the type after `new`, or give the place the type of a struct or a class.

## Failing example

```mora
// error: MR0154
public struct Point {
    public X: int;
    public Y: int;
}

var p = new { X = 3, Y = 4 };
```

## Fixed example

```mora
// expect: 7
public struct Point {
    public X: int;
    public Y: int;
}

let p: Point = new { X = 3, Y = 4 };
Console.WriteLine(p.X + p.Y);
```
