# MR0113: a modifier that does not apply to the declaration it is on

A modifier is written on a declaration it says nothing true about. `const` declares a constant, a value fixed at compile time, and only a field with an initializer, of a struct, a class or a union or in a namespace, is one. On anything else it misleads: a getter computes its value on each read, as in `const Limit: int => 10;`; a function, a method, a constructor or an indexer runs as code; a type declares a type; and a parameter takes its value from each call.

Remove the modifier. The fix removes `const` and keeps the declaration. When a value fixed at compile time is meant, write a field with an initializer instead: `const Limit: int = 10;`.

An interface has no fields and an extension adds none, so `const` on a field there, as `const Limit: int = 10;` in an interface, gets no fix: removing `const` would leave a field that cannot be there, error `MR0115`. Only the author knows what is meant. The same holds for any member that would be `MR0115` without `const`, as `const ~Buffer() {}` in an interface or `const this[i: int]: int => i;` in an extension, and for a `const` accessor of such an indexer: there is no fix, and the note says why the member cannot be there. A shared value is a constant in the namespace, next to the interface or the extension, or in the type itself; a value each implementing type gives is a static abstract getter, `static abstract Limit: int;`.

## Failing example

```mora
// error: MR0113
public struct Counter {
    public const Limit: int => 10;
}
```

```mora
// error: MR0113
public interface IBuffer {
    const Limit: int = 10;
}
```

## Fixed example

```mora
// expect: 10
public struct Counter {
    public const Limit: int = 10;
}

Console.WriteLine(Counter.Limit);
```

```mora
// expect: 10
public const Limit: int = 10;

public interface IBuffer {
    Size: int;
}

Console.WriteLine(Limit);
```
