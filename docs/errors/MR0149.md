# MR0149: a static member uses `this` or an instance member of its type, or a nested type's member uses one of a type around it

A `static` member belongs to the type, not to a value of it, so it runs with no value to read. Writing `this` in it, or naming an instance field, getter or method of the type by its bare name, which reads `this` implicitly, has nothing to refer to. The same holds for a local function or a lambda inside the static member. Mora rejects the use instead of reading a value that does not exist.

A type nested in another is a type of its own, so its members, `static` or not, have no value of the types around it either. Naming an instance field, getter or method of one of those types by its bare name is the same error. The nested type's own members and its own `this` stay allowed.

Take the value as a parameter and read its members through it, or remove `static` when the member works on a value of the type. In a nested type, take a value of the type around it as a parameter or keep one in a field. The error offers no fix, because the right one depends on how the member is called.

## Failing example

```mora
// error: MR0149
public struct Counter {
    public Count: int;

    public static Doubled(): int => Count * 2;
}

Console.WriteLine(Counter.Doubled());
```

## Fixed example

```mora
// expect: 6
public struct Counter {
    public Count: int;

    public static Doubled(c: Counter): int => c.Count * 2;
}

let c = new Counter { Count = 3 };
Console.WriteLine(Counter.Doubled(c));
```
