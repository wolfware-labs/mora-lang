# MR0154: `new` of a type that is not a struct or a class, or without a type where no target type gives it one

A `new` without a type, as in `new()` or `new { X = 1 }`, creates the type its place expects: the declared type of the local it initializes, the return type of the function it returns from, or the type of the parameter it is passed to. That type must be a struct or a class, since those are what `new` creates.

Without a type, the error has two forms. Where the place expects no type, as for a `let` or `var` without a type or a `new()` written as a statement, there is nothing to create. An argument of a call with overloads expects the type that every overload able to take the arguments has at its position, and none when they differ. Where it expects a type of another kind, such as `int`, `string`, an option, an enum or an interface, `new` cannot create a value of it. The same holds for a type written after `new`: `new int()`, `new Color()` for an enum or `new T()` for a type parameter create nothing, because `new` creates only structs and classes. A union value comes from one of its cases instead, as in `Json.Bool(true)`. In every case only the author knows which type or value is meant, so there is no fix: write the type of a struct or a class after `new`, give the place such a type, or write the value another way.

## Failing example

```mora
// error: MR0154
public struct Point {
    public X: int;
    public Y: int;
}

var p = new { X = 3, Y = 4 };
```

## Fixed example

```mora
// expect: 7
public struct Point {
    public X: int;
    public Y: int;
}

let p: Point = new { X = 3, Y = 4 };
Console.WriteLine(p.X + p.Y);
```
