# MR0127: a name that does not resolve to a declaration of the right kind

No declaration that the code can reach has this name. The compiler looks in the enclosing namespaces, the project's root namespace, its dependencies, `Std`, the namespaces that `using` directives open, and the prelude, and none of them declares it. The usual causes are a misspelled name, a missing `using` directive, or a path that names a folder that does not exist.

Correct the spelling, or write the path from a namespace the code can reach.

The same error marks a name in the wrong kind of position: a value, a function or a namespace where a type is expected, and a type, a type keyword or a namespace where a value is expected, as in `let a = Point;`, `let z = int;` or `Point()`. A nested type named through a value, as `p.Nested`, is this error wherever it stands, as the receiver of a member too. A type names no value; for a struct, `new Point { ... }` creates one.

## Failing example

```mora
// error: MR0127
//@ file src/Program.mr
using App.Stores;

Console.WriteLine(Count());
//@ file src/Store/Users.mr
internal Count(): int {
    return 3;
}
```

## Fixed example

```mora
// expect: 3
//@ file src/Program.mr
using App.Store;

Console.WriteLine(Count());
//@ file src/Store/Users.mr
internal Count(): int {
    return 3;
}
```
